
### 51 定时器/计数器

51 的计时器有编号为 0 和 1 的两个，并且每次希望用它们实现中断时，计时器有 4 种模式可选，以及一些其它的控制类型。这些类型设置通过 `TMOD` 字节完成。

`TMOD` 字节的 8 位中，高 4 位控制 T1 ，低 4 位控制 T0 。具体来说：

```
GATE    C/T    M1    M0     GATE    C/T    M1    M0
========== T1 ===========  ============ T0 ==========

一般来说，大多数时候如果我们要用定时器中断实现一个计时循环，都是取
 0000 0001
也就是 #01H. 这时定时器0为16位模式，作为定时器工作。
```

其中：
1. `GATE` 为门控位，通常来说置零即可，表示仅由软件控制启动。
2. `C/T` 表示要选择定时器功能还是计数器功能。 0 代表定时器（数内部机器周期），1 代表计数器（数外部引脚信号）。
3. `M1M0` 两位共可以表示 0, 1, 2, 3 ，分别代表四种工作模式。

这四种工作模式分别是：
0. **13 位定时/计数器**。这主要是为了兼容早期的 MCS-48 系列，现在一般不用。
1. **16 位定时/计数器**。充分利用每个计时器的高低 8 位，共 16 位，一共最多可以数 65536 。溢出后，定时/计数器值清零，需要手动重新装载初值。
2. **8 位自动重装定时器**。把每个计时器的低 8 位（记作 `TLx` ）用来计数，高 8 位（记作 `THx` ）用来存放设定好的初值，这样只要溢出就可以自动完成重装。缺点是最多只能数 256 ，优点是对于需要精确计时的场景可以消除手动重装的计时误差。
3. **分体模式**。该模式下，T0 被拆分为 TL0 和 TH0 ，TL0 占用其它所有原本关于 T0 的资源，TH0 临时借用所有关于 T1 的资源。这种模式主要是为了让你在 T1 被占用时仍然有两个独立计时器可用，相当于临时把 T0 和 T1 映射到了 TL0 和 TH0 上，并缩短长度为 8 位。

设置完毕关于定时器的标志位后，通过 `TR0` 和 `TR1` 这两位来控制定时器的启停。只要为 1 ，定时器/计数器就工作，否则就保持当前值冻结，除非你手动重装或者使用了模式 2 来自动重装。


### 51 中断系统

在 51 单片机中，中断系统总体上呈现这样的结构：

![[fae8fdb9a92842af81161726e8edf6b9.jpg]]

这张图按照从左到右的顺序来看，总共分为 4 个部分：

##### 是否收到中断

`TCON` 和 `SCON` 左侧的部分。

TCON 即 Time Control，SCON 即 Series Control ，分别作为是否收到中断的标志位。左边一共有 6 条线路，分别是外部中断 0 、计时器 0 、外部中断 1 、计时器 1 ，以及一组串行中断输入。

**两个外部中断口可以通过 `IT0` 与 `IT1` 两个标志位来控制触发类型**，设置为 0 时，代表低电平触发，即当检测到外部中断口上为低电平就触发；设置为 1 时，代表下降沿触发，即当检测到端口上电平从高电平转变为低电平时触发。对于串行口， `RX` 代表接收， `TX` 代表发送，两者对应的标志位为 `RI` 和 `TI` ，这两个标志位经过或门接入，也就是说读和写任意一者发出中断时都会记录到串行口中断上。


##### 是否允许 CPU 理会中断

`IE` 这一组标志位负责控制 CPU 是否理会中断。从上一部分进入的中断信号最终表现为 5 路，分别体现在 TCON 和 SCON 中，其中 SCON 中的两个标志位共同体现中断情况。 `IE` 通过两层允许机制来控制 CPU 是否听取中断： `EA` 负责总允许， `EA` 关闭时，任何中断都不会被传到下一层；EA 开启时，5 个中断源各自还有一个分开关，负责控制是否启用该中断。



##### 如何分配中断优先级

在接收到中断、确定要响应之后，就进入第三部分，即为这个中断分配一个优先级。同样是一组 5 位的状态位 `IP` ，各自控制一路中断的优先级。总共允许两种优先级，即高级中断和低级中断。每个状态位置 1 时代表高级，置 0 时代表低级。**高级中断事件可以打断低级中断事件**，但当同一层级中多个中断事件同时发生时，按照自然顺序处理这些中断。所谓自然顺序，就是按照上面图中画出的从上到下的顺序，也就是它们对应的中断入口地址从小到大的顺序。例如现在两个高级中断“外部 0 ”和“定时器 1 ”同时发生，那么根据自然顺序，先进入“外部 0 ”的程序，完成返回后再立刻进入“定时器 1 ”的程序，然后返回主程序。



##### 最终执行中断

完成排序后，按顺序将中断地址送 CPU ，开始执行中断程序。



根据上面这 4 个部分的语义，容易知道，只有第 2、3 部分中用到的标志位是我们可以更改且应当更改的——它们的值代表我们预期的中断处理模式。第 1 部分代表是否接收，这是客观事实的反映，不应当人为更改；第 4 部分是最终执行，会由系统自动完成，不需要人为更改。

当中断使能存在打开的线路时，CPU 会在每个机器周期的 S6 阶段寻找一遍中断请求，如果存在则立即将其优先级排队，然后：
1. 已经完成更高级中断内容；
2. **当前指令执行完毕后**；
3. 如果上面说的“当前指令”是 `RETI` 或者访问 SFR 中的 `IE` 或 `IP` 这三者之一，那么**至少再执行一条指令**；

然后才会响应这个中断。也就是说，假设你在机器周期 T 发出一个高级中断，而此时 CPU 正在执行另一个高级中断的 `RETI` ，并且返回后主程序的第一句话就是 `MUL  AB` ，那么将会：
1. 等待 `RETI` 完成。
2. 完成后，必须至少执行一条指令，因此需要等待 `MUL  AB` 完成。
3. 完成后，紧接着的下一个机器周期中开始处理你的中断。

这样一来，你的中断从发出到实际响应需要间隔 7 个机器周期，具体构成为：
1. `RETI` 的最后 1 个周期；
2. `MUL  AB` 的 4 个周期；
3. 花 2 周期为你的中断压栈（硬件 `LCALL` ）。


确定响应中断后，CPU 会完成这些事情：
1. 置位响应的“优先级状态”触发器。这是用于阻断其它同级或低级的中断请求。这个触发器不需要用户手动管理。
2. 自动清除中断标志（除了串行口的 `TI` 和 `RI` ），恢复到无接收状态。
3. 自动保护断点、压栈弹栈管理。

这里所谓的自动，是指你应当使用 `RETI` 。如果在中断中使用 `RET` ，断点保护可以正常进行，也可以返回主程序位置，但是关于中断的 SFR 管理就不会发生。因此不能混用 `RETI` 和 `RET` 。


当中断确定开始处理时，以下内容程序自动维护，不需要用户参与：
1. **断点保护**：进入服务之前的 PC 地址会被自动压入堆栈。
2. **设置中断优先级状态**：表示当前正在处理某个级别的中断，等于或低于这个级别的中断就不要来打断了。
3. **自动清除（部分）中断标志**：除串口中断的 `RI` `TI` 外，自动把表示中断发生的标志位重新设置为 0 。相当于接了任务就把单子撕下来，不要一直挂着了。

以下是程序不会自动维护的，需要用户自己动手：
1. **通用寄存器保护**：例如 `A` `B` `DPTR` `R0~R7` ，这些值如果你不想要在中断中改变它们，或者暂时要借用一下，那么你要自己写入栈，并且在返回之前自己倒过来写一遍出栈。
2. **程序状态字 `PSW`** ：同理不要忘了程序状态字，如果你只保护 `A` 而不保护 `PSW` ，并且服务中又复用了 `A` ，那么大概率离开服务程序的时候你会得到一个与 `A` 状态不匹配的 `PSW` ，这是危险的。
3. **模式 0 、1 、3  下的定时器初值**：除了自动重装，其它的定时器中断后初值要自己在服务程序中手动装回去。




### 使用定时器/计数器中断的标准写法


根据上面的论述，一个合理的中断启用写法是这样的：假设使用 12MHz 晶振，需要完成的任务是定时 50ms ，并在中断中反转 `P1.0` 引脚。这里不需要用到外部中断，但为了充分展示带有中断的程序写法也将其纳入了。

```
    ORG   0000H           ; 复位向量地址
    LJMP  START           ; 跳转到初始化程序
    
    ORG   0003H           ; 外部中断 0 入口地址
    LJMP  INT0_ISR        ; 跳转到外部中断 0 服务程序

    ORG   000BH           ; 定时器 0 入口地址
    LJMP  T0_ISR          ; 跳转到定时器 0 服务程序

; ==================================================== 主程序

    ORG   0100H           ; 程序起始地址
    
START:
    ; --- 第一步：设置工作方式 (TMOD) ---
    ; 设置 T0 为模式 1 (16位定时器)，且不影响 T1
    MOV   TMOD, #01H      

    ; --- 第二步：计算并装载初值 (TH0/TL0) ---
    ; 假设 12MHz 晶振，定时 50ms = 50000us
    ; 初值 = 65536 - 50000 = 15536 (3CB0H)
    ; 定时器总是正计时，因此把上限减去计时长度就是初值
    ; 由于是 16 位模式，要分高低位装载
    MOV   TH0, #3CH       
    MOV   TL0, #0B0H

    ; --- 优先级与触发方式设置 ---
    SETB  IT0             ; IT0 = 1: 外部中断 0 设置为下降沿触发
    SETB  PT0             ; PT0 = 1: 定时器 0 设置为高优先级
    CLR   PX0             ; PX0 = 0: 外部中断 0 设置为低优先级

    ; --- 第三步：开启中断控制 (IE 寄存器) ---
    SETB  EX0             ; EX0 = 1: 允许外部中断 0
    SETB  ET0             ; ET0 = 1: 允许定时器 0 中断
    SETB  EA              ; EA  = 1: 开启总中断开关

    ; --- 第四步：启动定时器 (TR0) ---
    SETB  TR0             ; TR0 = 1: 定时器 0 开始计数

    ; 主循环：程序在此等待中断发生
MAIN_LOOP:
    SJMP  MAIN_LOOP       ; 原地跳转，等待中断

; ==================================================== 中断服务程序

; 外部中断 0 服务程序
INT0_ISR:
    PUSH  ACC             ; 保护现场
    PUSH  PSW
    PUSH  DPH
    PUSH  DPL
    
    ; [此处添加外部中断处理逻辑]
    ; 例如：SETB P1.1
    
    POP   DPL             ; 恢复现场
    POP   DPH
    POP   PSW
    POP   ACC
    RETI

; --- 第五步：定时器中断处理 (T0_ISR) ---
T0_ISR:
    PUSH  ACC             ; 保护现场
    PUSH  PSW

    ; 重要：模式 1 必须手动重装初值
    ; 否则下次定时将从 0000H 开始（约 65.5ms）
    MOV   TH0, #3CH       
    MOV   TL0, #0B0H

    ; [此处添加定时执行的任务逻辑]
    CPL   P1.0            ; 翻转 P1.0，如果是接 LED，则会看到闪烁

    POP   PSW             ; 恢复现场
    POP   ACC
    RETI                  ; 中断返回

    END
```


通常来说，综合考虑情况下，如果系统只有一个中断源，那么一般可以在 3~8 个机器周期内响应这个中断。对于典型的 12MHz 单片机，这个延迟在微秒级别，相对比较准确。
