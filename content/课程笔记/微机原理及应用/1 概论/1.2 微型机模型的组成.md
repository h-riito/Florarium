 
### Ex 补充

- Cy 与 Ov 是常见的两种标志位，不过根据本课程的定义，Ov 衡量的是有符号数加减运算的溢出情况。因此，对于无符号数的“溢出”，应该使用 Cy 判断。
- DR/AR 缓冲的作用是隔离内外总线，同时稳定总线上传入的信号。
- 现代 CPU 有流水线、等待、冒险处理等机制，但对于 51 这样的简单微机来说不存在，整机各个部件都在预先设计好的周期状态下运行。



## 1 微机基本结构

微机的结构层次可以分为个层级：
1. 最底层的是**基本元器件**，包括二极管、三极管、场效应管、电阻、电容等等；我们学过的模电课中已经介绍了这些元件的特点。
2. 由上述元件构成**基本逻辑门电路**，例如与或非门等等。这是数电课要涉及的内容。
3. 由逻辑门电路组成**基本功能电路**，包括 JK 触发器、D 锁存器、计数器、编码器、译码器、加法器、乘法器、存储器、AD/DA 等等；这也是数电课的内容。
4. 由基本功能电路构成**微处理器**，能够在时序逻辑控制下自动循环执行预置指令的电路系统。这是本课程要研究的内容。

计算机的结构至少包括：CPU（包括**运算器**、**控制器**），**存储器**（分为**程序存储器**/**数据存储器**），**输入输出设备**。这些组成顾名思义，功能较好理解。

### 运算器部分

运算器在图中包括了 ALU、A、F 这三个模块。

#### ALU / 算术逻辑单元

观察框线中左上角较大的那一个模块。ALU 的主要作用是**完成数据处理和加工**，包括**数值运算**和**非数值运算**。最基本的加减乘除、与或非、位运算等等，都是在这个单元中完成的。它是 CPU 中真正实现计算的核心模块。具体要完成的运算由**操作控制命令**决定，在上面的示意图中用上方的一排 C 表示。

#### A / 累加器 Accumulator

ALU 总共接受两个输入，其中一个就来自于累加器。累加器在 ALU 运算之前向它**提供操作数作为输入**，而在 ALU 运算完毕后**保存它的结果**。ALU 的另一个输入从它右侧的那条总线传入，具体来源可以是多个其他模块。由于 A 中的内容总是传入 ALU ，算完又返回，所以得名累加器。累加器自身也有总线和其他模块连通。

#### F / 标志寄存器 Flag

标志寄存器又称为**程序状态字 PSW/Program State Word** ，用于存储 ALU 运算结果的状态，例如有没有发生进位、数据有无溢出、结果是否为零等等。ALU 的运算仅仅是完成运算任务，因此如果要表达关于结果的额外信息，需要查看 PSW 来确认。

不同的 CPU 内标志寄存器的标志数目和具体规定也有不同，但通常有下面几种常见的标志位：
1. **进位标志 Carry/Cy**：两个数加减时，如果最高位发生了进位或者借位，那么 Cy 就置 1 ，否则置 0 。除了加减之外，比较、循环、移位操作也会影响。
2. **零标志 Zero/Z**：如果 ALU 算出的结果为零，那么 Z 就置 1 ，否则置 0 。
3. **符号标志 Sign/S**：对于有符号数的计算，可以借助 S 来表达符号信息。它总是和 ALU 的运算结果中最高位保持相同，因此置 1 表示负数，置 0 表示正数。
4. **奇偶标志 Parity/P**：奇偶标志用来表示逻辑运算的结果中 1 字码的个数是奇数还是偶数。一般规定奇数置 1 ，不过不同机器规定有所不同。
5. **溢出标志 Overflow/OV**： 溢出标志用于表示当前 ALU 计算结果是否溢出了。所谓溢出是指，两个较大的正数相加（或两个较大的负数相加）时，结果溢出到了符号位，导致结果变成了负数。因此溢出标志只对有符号数的计算有效。通常，**检查是否溢出只需要检查最高位和次高位的进位标志的异或值**。例如，对于八位存储的有符号数，只需$$\text{OV}=\text{D}_{6\text{CY}}\oplus \text{D}_{7\text{CY}}$$这是因为，如果计算结果的最高位（即符号位）和次高位都没有进位，那么结果正常；都进位，那么最高位被改变两次，相当于没有更改（例如一个正数加一个负数。由于负数由补码存储，因此这是正常的）；只有发生一次进位的情况下最高位改变一次，相当于符号被错误改变了。
6. **辅助进位标志 Auxiliary Carry/AC**：辅助进位标志也被称为半进位标志 H 。它标志 $\text{D}_{3}$ 有没有向 $\text{D}_{4}$ 进位（ $\text{D}_{0}$ 起）。 置 1 代表有进位。


### 控制器部分

控制器在图中包括了 PC、IR、ID、PLA 四个部分。

#### PC / 程序计数器 Program Counter

程序计数器又称为**指令地址指针**，用来**存放内存中下一条指令的地址**。通常来说，程序在内存中的存储方式是逐条、逐个、连续存储的，因此每次取出一条指令，PC 只需要自加 1 即可。如果程序包含了转移、调用、返回等等改变指令序列的操作，那么这个操作会被传到 PC ，并使其重新指向正确的指令地址。

#### IR / 指令寄存器 Instruction Register

指令寄存器存储当前 PC 取出的一条指令。

#### ID / 指令译码器 Instruction Decoder

指令译码器接受 IR 传来的指令，并将其译码。

#### PLA / 操作控制部件 Programmed Logic Array

操作控制部件接受指令译码器传入的、经过译码的指令，并发出控制命令 C 。

### 寄存器部分

存储器和前面说的运算器和控制器之间**并不是非此即彼的关系**，上面说到过的 A、IR、ID、PLA、PC、F 都是寄存器。可以看到，凡是不执行运算操作的，都是寄存器，它们主要的功能就是负责记录自身的数据。

上面还没有提到的寄存器介绍如下：

#### DR / 数据寄存器 Data Register

数据寄存器主要负责存储 CPU 内部总线和外部总线之间的缓冲数据。它可以暂存指令，或者指令的操作数，或者操作数的地址。

#### R / 寄存器组 Register

寄存器组是 CPU 内部的一组若干个寄存器，用于暂存数据、地址等等信息。注意它不等于我们说的内存。通常来说，寄存器组还可以分为专用寄存器组和通用寄存器组。不同 CPU 的寄存器组构成通常是不同的，但它的特性却和程序运行速度高度相关。用户必须清楚寄存器组的构造才能设计出更适合该种 CPU 的程序。

#### AR / 地址寄存器 Address Register

和 DR 类似，它也负责 CPU 内部总线和外部总线之间缓冲的数据，只不过它存储的是地址信息。


### 存储器

![[Pasted image 20260309134723.jpg]]

RAM 的基本结构一般由 4 个部分组成，即图中的**存储矩阵、地址译码器、读写控制电路、三态双向缓冲器**。此外，它与外部有三条总线相连，即地址总线 AB ，控制总线 CB ，数据总线 DB 。

#### 存储矩阵

存储矩阵是一个按照地址访问的一维线形空间。图中展示的是一个由 256 个存储单元构成、每个存储单元有 8 位的存储电路。每 1 位基本存储电路可以存储 1 位二进制数。

这里所说的 $256\times 8$ 只是一个例子，实际上不同的 RAM 中存储矩阵的尺寸可以各不相同。例如，可以有深而窄的矩阵，如 $16384 \times 1$ ，每一个存储单元只能存储 1 位；或者用于显存的 RAM ，通常具有很宽的位长，如 $\times 32$ ，因为图像处理需要很深的数据吞吐量。

#### 地址译码器

以上面的 256 单元 RAM 为例，要给它们编制地址系统，就至少需要 8 位长的地址，即两位十六进制数，从 00H 到 FFH 。因此，若 CPU 需要访问某个存储单元，它需要通过地址总线 AB 给出单元地址，再由地址译码器将其翻译为对应的存储单元，完成“选中”操作。

#### 读写控制电路

除了选定地址以外，CPU 还要向 RAM 发出指令，指令通过 CB 传到控制电路，并对选中的存储单元执行具体的操作，例如读或写。读操作即将制定地址对应的存储单元中的数值通过 DB 送回 CPU ，而写操作即通过 DB 送来数据，覆盖到指定的存储单元中。

#### 三态双向缓冲器

三态双向缓冲器的作用在于断开不必要的总线连接。由于总线通过高低电平两种状态来传递数据，而当某条总线不需要使用时/正在被其他模块使用时，额外的接入会导致冲突，因此需要一个“阀门”，不想要与总线连接时将模块从总线上断开。这里的三态即指包含除了高低电平以外的第三态，即**高阻状态**。高阻状态下即相当于断路，避免模块与总线连接。

#### I/O 接口

I/O 接口负责接入外部设备。每个接入的外设都有一个固定的地址，在 CPU 的控制下实现输入输出操作。

## 2 模型机的工作过程

#### 指令和指令系统

任何计算机都有它的指令系统，但这些指令通常都遵循下面这种通用的形式：$$操作码\text{OP}\qquad 操作数/地址$$指令在计算机中是以一组二进制编码来表示和存储的，这样的编码我们称为**机器码/机器指令**。 

一条指令在执行时，需要经过两个阶段：**取指阶段**和**执行指令阶段**。这两个过程加在一起占用 3 个 CPU 周期。其中取指阶段占用 1 个 CPU 周期，执指阶段占用 2 个 CPU 周期。不同指令具体流程不同，但具体来说，可以概括为下面的过程：
1. 第 1 周期中，PC/Program Counter 给出指令地址，地址经过地址总线 AB 传到 RAM ，RAM 取出指令，同时 PC 自增 1 ，指向下一条指令。RAM 取出的指令通过控制总线 CB 送回 CPU ，并由 PLA/Programmed Logic Array 进行指令的译码。
2. 第 2 周期中，CPU 根据译码后的指令，发现需要操作数，于是又向 RAM 发送一个地址。RAM 译码该地址，定位内存单元。
3. 第 3 周期中，RAM 将对应地址的操作数通过 DB 送回 CPU 。送来的数据或是进入累加器 A ，或是直接进入 ALU ，和指令一起完成运算。运算结果送回累加器 A ，准备下一个指令操作。

#### 程序的执行过程

程序是按照某种要求编排的指令序列，这些指令有次序地放在存储器 RAM 中，在计算机工作过程中逐条取出并执行。以下面这个程序为例：“ $15\text{H}+30\text{H}$ ” ，即两个十六进制数的加法。它在我们假定的 RAM 中是这样存储的：

|  地址   |     内容      |         含义          |
| :---: | :---------: | :-----------------: |
| `00H` | `0111 0100` |     “取数指令”的操作码      |
| `01H` | `0001 0101` | 操作数的数值 $15\text{H}$ |
| `02H` | `0010 0100` |     “加法指令”的操作码      |
| `03H` | `0011 0000` | 操作数的数值 $30\text{H}$ |
| `04H` | `1000 0000` |  “原地踏步”的操作码（占两字节）   |
| `05H` | `1111 1110` |  “原地踏步”的操作码（占两字节）   |
|   …   |      …      |          …          |

以这个程序为例，说明工作步骤：

第一 CPU 周期开始，取指阶段开始：
1. PC 指向 `00H` ，将该地址送到寄存器 AR ；
2. 一旦送入 AR ，PC 立刻自增，指向 `01H` ；
3. AR 将地址经过地址总线送到 RAM ，RAM 译码后选中其中的 `00H` 对应的存储单元；
4. PLA 发出读指令。
5. RAM 读出 `00H` 中的内容，经过数据总线（虽然这是指令的操作码，但它是通过数据总线传输的）送到 DR，并经过 IR ，ID ，完成译码。
6. 译码后发现是取数操作。第一周期结束，取指阶段结束。

第二 CPU 周期开始，执指阶段开始：
1. PC 送 `01H` 到寄存器 AR ；
2. 一旦完成，PC 立刻自增，现在指向 `02H` ；
3. AR 将地址送到 RAM ，RAM 译码后选中对应的 `01H` 存储单元。
4. PLA 发出读指令。
5. RAM 将其中的数值经过数据总线送到 DR 。第二周期结束。

第三 CPU 周期开始：
1. 由于这时取出的是操作数，因此 PLA 不再让它去 IR 那一边，而是进入运算器这一侧。为了方便起见，我们假设它进入累加器 A 。
2. A 收到数值 `15H` 。第三周期结束，执指阶段结束。


在这个过程中，注意以下特点：
1. 最终 PC 自增了 2 次。从流程可以看出，PC 的自增次数取决于这条指令占用了多少存储单元，而和指令条数没有必然联系。这很好理解，因为 PC 负责记录当前执行到了 RAM 的第几个地址。
2. 为什么 PLA 能够发出读指令？是什么信息让它发出读指令的？PC 又是怎么做到准时发送地址的？它发送地址开启下一阶段的时候凭什么知道上一阶段已经结束了？这些问题的答案都是 CPU 的时钟决定的，简单来说，这些模块实际上并不需要判断自己是否应该做出指令，而是时钟逻辑已经“写死了”，例如“第一周期开始时，PC 必须发送当前地址”。反过来说，它们只是在等下一个时钟。也就是说，如果时钟太快，那么就算当前阶段的任务没有完全完成，PC 也会立刻发送一个地址，PLA 也会立刻乱发一个读指令。
3. 第二周期和第三周期内容那么少，为什么不合并成一个周期？这涉及到时序稳定性的问题，目前只需要默认微机都是这样设计的即可。
