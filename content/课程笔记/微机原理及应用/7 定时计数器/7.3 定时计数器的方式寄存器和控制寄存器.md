
### TMOD 寄存器

51 的计时器有编号为 0 和 1 的两个，并且每次希望用它们实现中断时，计时器有 4 种模式可选，以及一些其它的控制类型。这些类型设置通过 `TMOD` 字节完成。

`TMOD` 字节的 8 位中，高 4 位控制 T1 ，低 4 位控制 T0 。具体来说：

```
GATE    C/T    M1    M0     GATE    C/T    M1    M0
========== T1 ===========  ========== T0 ===========

一般来说，大多数时候如果我们要用定时器中断实现一个计时循环，都是取
 0000 0001
也就是 #01H. 这时定时器0为16位模式，作为定时器工作。
```

其中：
1. `GATE` 为门控位，通常来说置零即可，表示仅由软件控制启动。
2. `C/T` 表示要选择定时器功能还是计数器功能。 0 代表定时器（数内部机器周期），1 代表计数器（数外部引脚信号）。**作计数器使用时，只能检测 P3 上的 T0/T1 管脚的下降沿**。
3. `M1M0` 两位共可以表示 0, 1, 2, 3 ，分别代表四种工作模式。

这四种工作模式分别是：
0. **13 位定时/计数器**。这主要是为了兼容早期的 MCS-48 系列，现在一般不用。
1. **16 位定时/计数器**。充分利用每个计时器的高低 8 位，共 16 位，一共最多可以数 65536 。溢出后，定时/计数器值清零，需要手动重新装载初值。
2. **8 位自动重装定时器**。把每个计时器的低 8 位（记作 `TLx` ）用来计数，高 8 位（记作 `THx` ）用来存放设定好的初值，这样只要溢出就可以自动完成重装。缺点是最多只能数 256 ，优点是对于需要精确计时的场景可以消除手动重装的计时误差。
3. **分体模式**。该模式下，T0 被拆分为 TL0 和 TH0 ，TL0 占用其它所有原本关于 T0 的资源，TH0 临时借用所有关于 T1 的资源。这种模式主要是为了让你在 T1 被占用时仍然有两个独立计时器可用，相当于临时把 T0 和 T1 映射到了 TL0 和 TH0 上，并缩短长度为 8 位。方式 3 是设置给 T0 的，所以这时 T1 那里不需要把模式填写成 3 。注意虽然这种情况常常在 T1 用来作为波特率发生器的时候使用，但并不意味着 T0 填写模式 3 后 T1 就自动开始作为发生器计时，在 SCON 没有指定、TMOD 没有变成模式 2 之前它保持停止。换句话说，T0 的模式 3 只是针对 T0 而言，想要把 T1 用作波特率发生器，所有相关项要单独配置，两件事情不干扰。不过注意，因为此时所有用于控制 T1 的 TCON 内容都被抢走了，因此这种情况下 T1 通过模式配置来控制启停，也即你把它放进模式 2 它就自动开始计时了，放进模式 3 就停止了。

设置完毕关于定时器的标志位后，通过 `TR0` 和 `TR1` 这两位来控制定时器的启停。只要为 1 ，定时器/计数器就工作，否则就**保持当前值冻结**，除非你手动重装或者使用了模式 2 来自动重装。


要注意的是， `TMOD` 这个寄存器是**不能位寻址的**，上面每一位的名称只是我们的呼号，不能直接写某一位。你必须确定全部位，一次性写一个 8 位值进去，比如 `MOV  TMOD, #01h` 。
