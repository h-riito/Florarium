
### 本节注意点

- 须知对于 **SFR 中的位寻址，位地址相邻不代表物理相邻**。例如 87h 作为位地址理解时，指的是 80h 字节的第 7 位，即最高位，可以表示为 `80h.7` ，而 88h 作为位地址理解时，指的是 88h 字节的第 0 位，即最低位，可以表示为 `88h.0` ，它们之间相隔了 7 个字节。只有片内 RAM 的位寻址区地址相邻等价于物理相邻。
- 须知 **SFR 中并不是所有 128 个字节都填充了有用的功能寄存器**。对于那些没有真实寄存器的地址，也不能拿来当 RAM 使用。
- 注意 RAM 部分的位寻址区的位地址是从 `00h` 编号到 `7Fh` 的，而不是对齐到字节地址从 `20h` 开始。这一点和 SFR 中的可位寻址字节不同。



### 程序存储器

程序存储器存放**程序**以及**表格常数**。表格常数虽然不是程序，但它不能在断电之后丢失，所以需要放在 ROM 中。比如，我们经常写 `MOV P0, #0FFH` ，那么这个 `0FFH` 到底是怎么发出来的呢？必然有一个存放这个数的地方。因此这种数就需要存储在 ROM 中，作为这个单片机的“核心记忆”。

我们说程序存储从 `0000H` 开始，因此第一条指令必须放在这个位置。其他程序指令没有存放位置要求，但下面几个特定地址有固定含义：

![[Pasted image 20260329175846.png]]

这些地址的意思是，一旦中断源进入，中断事件发生，那么根据中断源的类型跳转到对应的地址开始操作，这个过程自动完成。因此，若你在设计的程序中需要用到中断源，那么就应该避开上面这部分地址区域，避免正常执行的程序进入中断跳转的区域。若你不需要用到中断源，那么忽略上述地址限制即可。

这些终端地址有规律，从第一个 `0003H` 开始，每隔 8 个字节（指程序空间，不是地址差值）就是下一个中断源入口地址。其中最后一个中断源是 52 系列单片机的功能，52 系列单片机有 3 个定时器。

你可以注意到第一个中断源入口地址很小，几乎紧挨着 `0000H` 。因此，若你要用中断源，特别是计时器 0 的话，你的程序开始时要在 3 条指令内立刻完成一个跳转动作，离开中断源指令区域。同样地，由于每个中断源入口地址后面只预留了 8 个字节的指令空间，如果你的中断源程序块不能在 8 个字节以内表达，那么你应当写一个跳转，去别的地方完成中断源程序。


前面我们说过，既然地址总线有 16 位，那么最多支持 $2^{16}\times 1\text{B}=2^6\times1\text{KB}=64\text{KB}$ 的存储空间。而 51 系列内置 ROM 为 4KB ，52 系列内置 ROM 为 8KB ，因此它们的 ROM 标号是这样组成的：
1. 对于 51 系列，如果 $\overline{\text{EA}}=1$ ，那么意味着启用内部 ROM ，从而内部 ROM 编 `0000H` 到 `0FFFH` 共 4K 个单元，外部 ROM 编 `1000H` 到 `FFFFH` 共 60K 个单元。如果 $\overline{\text{EA}}=0$ ，那么意味着直接使用外部 ROM ，这时外部 ROM 直接编 `0000H` 到 `FFFFH` 共 64K 个单元。
2. 对于 52 系列，如果 $\overline{\text{EA}}=1$ ，那么意味着启用内部 ROM ，从而内部 ROM 编 `0000H` 到 `1FFFH` 共 8K 个单元，外部 ROM 编 `2000H` 到 `FFFFH` 共 56K 个单元。如果 $\overline{\text{EA}}=0$ ，那么意味着直接使用外部 ROM ，这时外部 ROM 直接编 `0000H` 到 `FFFFH` 共 64K 个单元。
因此，无论怎么分配内外存储，总和不会超过 64KB 的数据量。

### 数据存储器

RAM 分为片内和片外两种，但它们之间的关系和 ROM 不同，它们的地址空间是独立的。片内 RAM 地址是从 `00H` 到 `FFH` ，而片外 RAM 地址是从 `0000H` 到 `FFFFH` 。也就是说，总共的可用数据存储量是 $256\text{B}+64\text{KB}$ 。这种结构也体现在指令上：例如取数指令 `MOV` 取的都是片内 RAM 的地址，若要取片外 RAM ，则需要写 `MOVX` ，这里的 X 就代表 Expand 。此外我们还有 `MOVC` ，这里的 C 代表 Code ，是指去 ROM 中取表格常数。根据取的对象位置的不同而需要写不同的指令，这是汇编语言软硬件结合特点的一个体现。

> [!NOTE]
> 取内部数据存储器，指令为 `MOV` ；取外部数据存储器，指令为 `MOVX` ；取程序存储器，指令为 `MOVC` 。也就是说，从指令上你不能区分取的是内部程序存储器还是外部程序存储器，这个逻辑和程序存储器的地址编号逻辑也是相统一的，程序存储器的地址编号无论内部外部各自有多少，总是连续地从 `0000H` 编到 `FFFFH` 。

具体的存储划分方式，51 系列和 52 系列有所不同，如下图所示：

![[Pasted image 20260329182616.png]]

其中，51 系列的内部数据存储器中只有低一半是真正的内部 RAM ，因此它的内部 RAM 大小只有 128B 。52 系列的 SFR 存储空间和内部 RAM 重叠，通过不同的寻址方式区分，所以它有 256B 的内部 RAM 。


这 `00H~7FH` 的内部 RAM 还有更详细的区分：

![[Pasted image 20260329183551.png]]

其中，较低的 32 字节平均分为 4 个区，每个区 8 个字节，每个字节对应一个工作寄存器，分别是 `R0` 到 `R7` 。这不同区之间的工作寄存器名字都一样，后面会学到可以用另一个寄存器来对这 4 组寄存器进行区分。理解这种设计可以参考我们学 C 语言基础时候遇到的特性，即外部变量可以和内部变量同名，但它们实际上是两个不同的变量。这里也类似，由于寄存器编号只有 8 个，有时我们需要频繁地存储程序中得到的结果，因此我们就可以在主程序里采用一套寄存器，子程序里采用另一套寄存器，虽然它们共用名称。那么也就是说最多可以使用同名寄存器来存储独立值 4 次。

在这较低的 32 字节上面是 16 字节的**位寻址区**。对于位寻址区，我们更常用的说法是 128 位。位寻址区的地址顾名思义，是逐个字编号的，如下图所示：

![[3c5dd4c1c7dabe8fcd620e907158cfcc.jpg|277]]

位寻址区主要用于给位运算存储。

从这里往上，也就是 `30H` 开始一直到 `7FH` ，都是通用的数据缓冲区，可以由用户自己分配。一般我们用它来进行临时的数据存储和堆栈构建。不过值得注意的是，上面说的划分是系统默认的划分，如果你已经确定你的整个程序不需要用到这些功能（如不需要 1、2、3 区以及位寻址区），那么你可以自己把这些位置当作通用数据缓冲区来使用，不会出现错误。

为什么我们强调这一点呢，因为还有一些寄存器是不能自己控制的。例如 PC 就是一个拒绝赋值的存储器。没有任何一条指令可以直接向 PC 赋值一个地址，只能通过跳转指令来间接改变 PC 的位置。

然后是内部数据存储器的高 128 字节，即特殊功能寄存器 SFR 。分布如下：

![[IMG_3592.jpeg|309]]

上面这张图直接看不太直观，这些地址是按照这样的规则编号的：
1. 首先，把每个字节进行编号，从 `80H` 到 `FFH` ，总共是高 128 字节。
2. 这每个字节的地址中，选出那些能被 8 整除的地址，换言之就是 8 个字节一组里面的排头，如 `80H` `88H` `90H` `98H` 等等。
3. 这些排头所在的字节是可以位寻址的，每个字节我们再细分成 8 位，准备给这 8 位编号。
4. 位编号时，直接把这 8 个位中的最低位沿用这一个字节的地址，然后依次增长。

所以，最终的地址分布是这样的：
1. 首先我们有 `80H` ，这个地址既可能代表 SFR 中的 `80H` 这个字节，也可能代表这个字节中最低那一位，因为它们俩的地址值都是一样的。
2. 然后有 `81H` 。这个地址既可能代表 SFR 中的第 `81` 字节，也就是排在第 `80H` 字节上面的那个字节，也可能代表第 `80H` 字节的倒数第二位，因为倒数第一位是 `80H` 。

所以，上面那张图中实际上只画出了可以位寻址的那些字节，每个画出的字节上面有一个空行，那个空行代表其余 7 个不能位寻址的字节。

对于那些可以位寻址的字节，其中某个位如果有名字，那么你在汇编程序中就可以直接指名道姓地拿来用，而不需要记住地址。也就是说这些是“预置的变量名”。例如，我们经常写的 `MOV P0, #0FFH` 和 `MOV 80H, #0FFH` 是一样的。

下面介绍几个专用寄存器的工作机制：

**程序计数器 PC** ：存放下一条要执行的指令地址。由于地址程序地址是 16 位的，所以寻址范围 64KB 。

**累加器 A/ACC** ：位于图中 `E0H` 位置，一个 8 位的寄存器。几乎所有运算都要经过累加器，以及当需要从外部读入一个数，再将数输出到其他管脚时，也要先经过累加器。

**B 寄存器**：位于图中 `F0H` 位置，一个 8 位的寄存器。B 寄存器和累加器配合使用，一般只会用于乘除指令中。51 单片机的乘除只有下面这两种做法：
1. 计算累加器和 B 寄存器中的数的乘积，结果的高 8 位放在 B 寄存器中，低 8 位放在累加器 A 中。即 A\*B=BA
2. 计算累加器 A 中的数整除 B 寄存器中的数，结果的商放在累加器 A 中，余数放在 B 寄存器中。即 A/B=A…B

程序状态字 PSW ：位于图中 `D0H` 位置，一个 8 位的寄存器，其中存放了很多有一定含义的状态位，分别如下：
1. **CY/PSW.7 ：即 Carry ，进位标志**。实际上也负责记录减法的借位，当加减发生进位或者借位时，将这个进位或者借位放在 CY 里。
2. **AC/PSW.6 ：即 Auxiliary Carry ，辅助半进位标志**。负责记录低 4 位加减时有没有发生进位或者借位。可以理解为为了和更老的 4 位机兼容用的标志。
3. **F0/PSW.5 ：即 Flag 0 ，标志位 0** 。它没有预先设定的含义，可以供用户自行调用。
4. **RS1, RS0/PSW.4, PSW. 3 ：即 Registry Space ，工作寄存器选择控制**。这两位共同表示一个数，即 0, 1, 2 或 3，代表选中内部 RAM 的四个寄存器区之一。
5. **OV/PSW.2** **：即 Overflow ，溢出标志**。当运算结果溢出时，置 1 ，否则置 0 。
6. PSW.1 ：这是未定义的位，可以由用户自行调用，但一般约定不使用该位。
7. **P/PSW.0 ：奇偶标志**，反应当前累加器 A 中存储的数的 1 的个数，如果是奇数，那么就置 1 ，否则置 0 ；即让 A 中的 1 的个数加上 P 总是偶数。

可见，除了 F0 和 RS 这三位，PSW 的其他位都在存储当前 ALU 运算的信息。



**堆栈指针 SP** 是一个 8 位寄存器，指向堆栈的**栈顶地址**。堆栈实际位置设置在片内 RAM 中，初始时 SP 一般指向 `07H` 位置，也就是工作寄存器 0 区的最上面一个字节。

这就有一个问题：如果我们不使用 1、2、3 区，那么没有关系；否则 SP 指向的堆栈位置会影响寄存器内容。因此，如果要使用其他工作寄存器区，我们需要在程序开始时把 SP 转移到其他位置。转移的办法就是给指针赋地址，即

```
MOV SP, #40H
```

`40H` 这个地址位于内部 RAM 的通用数据缓冲区，可以随便我们存储。

若要使用堆栈，只需要这样写：

```
PUSH ACC
```

这就代表把累加器中的数压栈。这时，SP 会先自增一个地址（ 8 位一单元 ），指向 `41H` ，然后在这个位置写上一个 8 位数。

对应地，如果要弹出，则写

```
POP B
```

这代表把当前的栈顶值弹出到寄存器 B 中。这时，SP 先读出栈顶的值，然后自减一个地址，回到 `40H` 。


除了存储数值，SP 还有一个功能是完成程序堆栈，即在执行子程序时用堆栈记录原本的主程序。例如，看下面这段程序（左侧的一系列数是地址，此处为了讲解方便而标出）：

```
		ORG 0100H         ;以下程序存储位置从0100H开始
0100H   MOV SP, #6FH      ;将数值6FH放入SP（即让SP指向地址6FH）
0103H   MOV R0, #30H      ;将数值30H放入R0
0105H   MOV A, #85H       ;将数值85H放入累加器A
0107H   PUSH ACC          ;将累加器A中的数值入栈
0108H   SWAP A            ;交换累加器A中的高4位和低4位
0109H   ANL A, #0FH       ;将A中的数和0FH做与运算，结果放入A
010BH   LCALL ASCII       ;长范围寻址ASCII标签
010EH   MOV @R0, A        ;将累加器A中的数值放到以R0中的值为地址的位置上
010FH   POP ACC           ;弹出堆栈中的值到累加器 A

		ORG 0300H         ;以下程序存储位置从0300H开始
ASCII:  ADD A, #30H       ;将累加器A中的值增加30H
        RET               ;返回主程序
```

前面发生的操作解释如下：
1. 一开始，将 SP 指向 `6FH` 位置，因此我们的堆栈第一个元素将会从 `70H` 开始。
2. 向存储器 R0 中存放了数值。
3. 向累加器 A 中存放了数值。
4. 把累加器 A 中的数值压入栈中。那么，这时 SP 指向 `70H` ，而内部 RAM 的 `70H` 地址将会存放数值 `85H` 。
5. 交换了累加器 A 中的高低位。那么这时 A 中存储的数值变成了 `58H` 。
6. 将 A 中的数值和 `0FH` 做了按位与运算。由于关于 0 的与都是 0，关于 1 的与结果和原来相同，所以这个操作相当于就是丢弃 A 中的高 4 位，也即现在 A 中存储的数值变成了 `08H` 。

接下来是关键部分：程序开始执行 `LCALL ASCII` 这一句。由于 PC 总是指向下一条要执行的指令，因此 PC 现在的值是 `010EH` ；同时运行到此处时 SP 指向 `70H` ，且这一位置存放了数值 `85H` 。
1. `LCALL` 的意思是 Long Call ，即在全部 64KB 空间中寻找标签为 `ASCII` 的子程序段。
2. 找到子程序后，为了执行子程序，PC 需要移动到子程序的第一条程序所在的位置。
3. 这时，SP 自动记录 PC 离开时的程序地址，即 `010EH` ，并将其按照先低位后高位的顺序入栈。也就是说， `71H` 会自动写入 `0EH` ，`72H` 会自动写入 `01H` ，然后 SP 指向 `72H` 。![[Pasted image 20260330153543.png|154]]
4. 自动入栈完成后，PC 跳转到 `ASCII` 标签所在的程序地址，开始执行子程序。
5. 子程序的操作是将累加器 A 中的数加上 `30H` 。 `30H` 就是 ASCII 中字符 0 的对应码值，所以这个操作是把数值转换为对应数字的字符码值。
6. 子程序完毕，PC 需要跳回。这时，SP 自动弹出两个元素，拼成完整的一个原地址，赋给 PC 。所以这时 PC 重新回到 `010EH` ，SP 重新指向 `70H` 。

剩下的操作解释如下：
1. 将累加器 A 中的数值放到以 R0 中的值为地址的位置上。此前 R0 存储 `30H` ，所以这一步把 A 中的 `38H` 这个数值放在了地址为 `30H` 的内部 RAM 上。
2. 弹出堆栈中的数值到累加器 A 。堆栈中剩下的值是 `85H` ，这个值现在赋给累加器 A ，然后 SP 向下移动，重新指向 `6FH` 。

从上面这个过程可以看出，堆栈实际上就完成了临时存储累加器 A 中的值的功能，等待 A 作为容器完成其他计算任务后，再把数值还回去。



**数据指针 DPTR** 是一个 16 位的专用寄存器，它可以单独使用，也可以分成两个 8 位的寄存器来使用。当它分成两个寄存器时，我们分别称其为 **DPH** 和 **DPL** ，对应高 8 位和低 8 位。它主要用来保存外部 RAM 的 16 位地址，也可作为**间址寄存器**。ROM 中的地址由 PC 来寻址，在外部 RAM 中完成对应功能的就是 DPTR 。

P0 P1 P2 P3 这四个专用寄存器对应的就是上一节我们分析端口硬件组成时说到的**锁存器**。

**串行数据缓冲器 SBUF/Serial Buffer** 是 8 位寄存器，虽然名字唯一，但在发送和接收时并不是同一个 SBUF 在工作，后面会介绍。
