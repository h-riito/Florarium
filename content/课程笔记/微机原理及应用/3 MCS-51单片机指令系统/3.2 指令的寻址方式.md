
寻址方式是指，**用什么方式寻找参与运算的数据的真实地址**。

MCS-51 单片机共有 7 种寻址方式。不同的寻址方式能够寻找的范围、解读地址的格式都可能不同。

### 1 立即寻址

拿出一个立即数，这种方式就是立即寻址。立即数总是存储在紧跟当前操作代码的后面。例如

```
MOV  A, #30H             ;两字节指令
MOV  DPTR, #8000H        ;三字节指令
```

由于立即数总是放在操作代码后面，因此这个数必然存在于 ROM 中。

值得注意的是，**像 `MOV  DPTR, #8000H` 这样的三字节指令必定是双周期指令**。这是因为，一个机器周期内最多对 ROM 读取 2 次，而三字节至少需要两个机器周期。我们又说过四周期指令只有乘除，因此这样的三字节指令肯定是双周期指令。



### 2 直接寻址

直接寻址的寻址空间只能是**内部 RAM 的低 128 字节 + SFR** 。注意这个表述，对于 52 系列单片机，内部 RAM 的高 128 字节和 SFR 重叠，此时仍然**不能**对高 128 字节的 RAM 进行直接寻址。

**直接寻址是访问 SFR 的唯一方式**。如果你看到了以其它形式写出的对于 SFR 的寻址，那么它实际上还是以直接寻址进行的。

直接寻址就是给出 `direct` 进行寻址，例如

```
MOV  A, 30H       ;双字节指令：第一字节给出操作，第二字节给出地址
ANL  30H, #30H    ;三字节指令：第一字节给出操作，第二字节给出目的地址，第三字节给出立即数
MOV  30H, 50H     ;三字节指令，类同
```



### 3 寄存器寻址

寄存器寻址是指用寄存器的名字来寻址，寻址空间是寄存器 `Rn` 、累加器 A 、 寄存器 B 、进位标志 Cy 、DPTR 。**这可以简单记作 R0~R7 + ABCD** 。凡不是这里名字的寄存器，都是转化到直接地址来寻址的，例如 Pn、PSW、SP 等等。但是这里还要额外注意一点的是，这条标准不是说凡出现都是寄存器寻址，它实际上也只是对 51 指令集的一个总概括。对于一些不常见的操作，例如 `mov  A, B` ，那么这里的 `A` 是寄存器寻址，但 `B` 一般是作为直接地址存储的。只有 `mul  AB` 这种操作中才作为寄存器寻址解读。

寄存器寻址和直接寻址的最大区别是寄存器的地址不需要在 ROM 中额外存储：

```
MOV  A, R3;     ;单字节指令
```

寄存器名已经融入在了操作码字节中。

需要注意的是寄存器寻址的范围。**不是任何有寄存器名的寻址都是寄存器寻址**。例如

```
MOV  P0, A
```

这里的 P0 并不在寄存器寻址的范围内。而且，由于访问 SFR 的唯一方式就是直接寻址，所以这个指令实际上会把 P0 翻译成地址再写进 ROM 中。这样，它就变成了一个双字节指令。



### 4 寄存器间接寻址

寄存器间接寻址就是以指定寄存器中存储的内容作为地址，去访问那个地址中的内容。这种寻址主要通过符号 `@` 来指定，并且寻址空间取决于你写的操作类型。在内部 RAM 中寻址可以写 `@R0 @R1 SP` ，而在外部数据存储器中寻址可以写 `@R0 @R1 @DPTR` 。

你可能会想，能不能在 `R0` `R1` 里面放上一个高 128 字节的内部地址，然后访问 SFR ？答案是**不行，直接寻址是访问 SFR 的唯一方法**。对于 51 ，这条寻址会无效；对于 52 ，这条寻址会寻到高 128 字节 RAM ，而不是 SFR 。

**也可以用 `R0 R1` 寻外部地址**。但是由于外部数据存储器是 16 位地址的，所以用 `@R0` 的方式最多只能寻址到外部 RAM 的低 256B 空间，**高位默认为全零**。若要完整寻址，则应该用 `@DPTR` 。

```
MOV  @R0, A     ;单字节指令
MOVX A, @DPTR   ;单字节指令
```





### 5 基址加变址间接寻址

这种寻址方式只有一种应用场景，写法很有限，就是我们前面遇到过的 `@A+DPTR` 和 `@A+PC` 。所以你现在理解了，为什么连作一个加法都要搬来搬去的汇编语言中可以明晃晃的出现加号这种写法，原来是固定指令。

这种寻址的应用场景就是**查表**。这里所说的表，是指写在 ROM 中的、掉电不丢失的常数表，就如前面的 ASCII 码表一样。因此，使用这种方式寻址的时候，我们总是写 `MOVC XXXXXX` 。从而，这种寻址的空间永远是程序存储器，即 ROM 。

你可以注意到，之前我们说 DPTR 用来在数据存储器中寻址，而这里却在 ROM 寻址中参与了。这是一种使用技巧，因为对于 `@A+PC` 而言，A 是 8 位的，PC 是 16 位且不接受赋值的，这意味着这样的寻址最多只能寻到当前 ROM 地址之后的 256 字节。如果你需要在之后的所有空间内寻址，就必须有一个可以控制的 16 位数。因此，可以先对 DPTR 作操作，再用 `@A+DPTR` 这种方式来对 ROM 全域寻址。

**注意这种寻址方式只能把结果放进累加器 A** 。

`MOVC A, @A+DPTR` ，是单字节指令。



### 6 相对寻址

相对寻址在工作方式上和其他寻址差别不大，主要差别体现在寻址目的上：相对寻址的最终目标是利用指令来改变 PC 的地址。从而，用到相对寻址的一定是一条**跳转指令**。

这里的偏移量是从 `-128` 到 `+127` ，即可以向前跳也可以向后跳。例如

```
JNZ   rel      ;双字节指令
```

JNZ 的意思是，Jump if Acc is Not Zero ，即若累加器 A 不为零则跳转。跳转偏移量 `rel` 是一个需要给出的常数，因此是写在 ROM 的数。



### 7 位寻址

位寻址在形式上和直接寻址一样，具体访问的到底是字节还是位完全依赖于**指令写法**来区分。例如

```
CLR    10H
MOV    10H, C
SETB   92H
```

这三条指令都是位寻址。因为：
1. `CLR` 指令定义就是将一个位或字节设置为 0 的指令（也可以用于 `CLR A` ）；
2. `MOV` 指令虽然不定性，但是 `C` 代表进位标志，是一个位，因此这种写法是把 `C` 值赋给 `10H` 这个位。
3. `SETB` 指令定义就是将一个位设置为 1 的指令。

位寻址的寻址空间显然是片内 RAM 的 `20H~2FH` 以及部分 SFR 空间。

注意如果指令不能显示地看出是位寻址，那么默认是字节寻址。例如：
```
MOV  B0H, 90H
```
它可以被解读为 P3 赋给 P1， 也可以认为是 P3.0 赋给 P1.0 ，但在默认情况下它作为字节理解。




值得注意的是累加器 A 有 `A` 和 `ACC` 两种写法，这两种写法代表的寻址方式不同，并且在堆栈那里有体现。写 `A` 时，执行的是寄存器寻址；写 `ACC` 时，执行的是直接寻址，即直接存储为 `E0h` 。堆栈的入栈和出栈操作只支持直接寻址，因此对于累加器，必须写 `ACC` 而不是 `A` 。
