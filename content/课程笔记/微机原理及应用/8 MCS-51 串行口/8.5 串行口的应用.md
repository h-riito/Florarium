

甲机的内部 RAM 的 `40H ~ 5FH` 单元中存储了一些 ASCII 码。现在需要把这些码在最高位上加上奇校验位，然后发送给乙机。波特率要求设置为 $1.2\text{ kbps}$ ，两机的晶振都是 $f_{\text{osc}}=11.0592\text{ MHz}$ 。

---

首先看通信部分。根据题目要求，可以选择模式 1 ，那么设置甲机的 `SCON = 0100 0000b = 40h` ，设置乙机的 `SCON = 0101 0000b = 50h` 。

然后将甲乙两机的定时器 1 都设置在工作模式 2 ，查表得初值应该是 `E8h` ，因此给它们的定时器 1 初值高低 8 位都设置为 `E8h` ，且 `TMOD = 0010 0000b = 20h` 。

其它中断配置按需设置。

接下来只需要考虑如何填写奇偶校验位。实际上奇偶校验位在硬件上已经有预留设计，那就是程序状态字 `PSW` 中的 `P` 这一位。这个位总是统计当前 `ACC` 中 `1` 的个数，奇数时为 `1` 。那么，我们只需要正常取出每个 ASCII 码到 `ACC` ，然后反转它的 `P` ，再把这个值放到最高位，就是奇校验了。

```
	mov    A, #ASCII      ; 取数
	mov    C, P           ; 奇数时为 1
	cpl    C              ; 取反
	mov    ACC.7, C       ; 回填最高位
```

这里移动到 `C` 是因为位操作中变换的核心只能在 `C` ，正如 `A` 在字节中的地位一样。

这种连接方式有如下特点：
1. 这是一种“**线与**”接法。线与接法要求所有接入者没有高电平输出能力，这时只要有一个接入者为低电平，整条线上就是低电平；只有当所有接入者都是高电平时，整条线上才是高电平。对于 51 单片机，P3 口是上拉电阻，因此它没有高电平输出能力，是靠上拉电阻维持，因此硬件上可行。
2. 通过 `SM2` 来选择点名模式还是广播模式。但是这里有一个问题：在点名对话之前，怎么让要对话的从机知道自己要接收，而其它的从机不接收？这里采用的是一种“**点名 + 对话 + 恢复**”流程。
   
   **点名**：首先，从机全部保持 `SM2 = 1` ，也即需要 `RB8` 验证。主机这时发送一个地址信息（具体是什么格式事先约好）并确保 `TB8 = 1` ，因此这时所有从机都会收到。另一方面，每一台从机都设计一个“握手程序”，对于收到的地址信息会先加以判断。如果这个判断中，主机发出的地址和自身相符，那么就把自身的 `SM2 = 0` ，其余从机保持不变。那么，对于这台被点名的从机来说，它将不再要求 `RB8 = 1` ，而其它从机仍然要求。
   
   **对话**：握手完毕后，主机开始发送消息，但保持 `TB8 = 0` 。这样一来，其它从机都会忽略这些消息，而由于目标从机不验证 `RB8` ，从而会收到消息。
   
   **恢复**：对话完毕后，主机又在保持 `TB8 = 1` 的情况下发出一个对话终止信息。所有从机这时都会收到这个信息，并将自身都调整为 `SM2 = 1` ，等待下一次点名。或者，也可以在对话末尾向从机发送一个约定的终止符，从机收到终止符后把自身 `SM2 = 1` 。

这套流程是 51 多机通讯的标准流程，它还可以作如下功能挂载：
1. 紧急广播：如果需要立刻进入全局广播模式，主机可以在 `TB8 = 1` 的情况下发送一个约定好的特殊地址，所有从机的条件判断中，遇到该地址就将自身 `SM2 = 0` ，全部进入恒聆听状态。


值得注意的是，不能把 PC 的 USB 转串口直接进行多机通讯线与连接，因为电平协议不同。
